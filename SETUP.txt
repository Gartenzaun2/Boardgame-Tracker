Boardgame Tracker - Scaffold v0.3

Neu in v0.3
------------
- EF-Core-10-Beziehungen vereinheitlicht: explizite Foreign Keys plus Navigationen.
- Navigationen sind von außen nicht frei setzbar; dadurch können FK und Navigation
  nicht versehentlich unabhängig voneinander gesetzt werden.
- Navigationen sind nullable, weil eine Beziehung fachlich existieren kann, obwohl
  die zugehörige Entity in der aktuellen Query nicht geladen wurde.
- Kein Lazy Loading / keine EF-Proxies. Verwandte Daten werden bewusst per Query
  bzw. Include geladen.
- Entity-Zustand wird stärker gekapselt (private Setter + fachliche Methoden).
- ArkNovaGroupPlayer ergänzt: Standardfarbe pro Gruppe und Person.
- ArkNovaGroupPlayer referenziert per zusammengesetztem FK eine echte
  GroupPerson-Mitgliedschaft.
- ArkNovaSessionPlayer referenziert per zusammengesetztem FK den dazugehörigen
  GameSessionPlayer.
- Echte Foreign Keys für angebotene und gewählte Zoopläne.
- Eindeutige Standardreihenfolge pro Gruppe und Spielerreihenfolge pro Partie.
- Eindeutige Arche-Nova-Farbe pro Gruppe bzw. Partie.
- Check-Constraints für positive Reihenfolgen/Platzierungen und gültige
  Zooplan-Auswahl.
- Versehentlich erzeugte EF-Shadow-Properties werden als Fehler behandelt.

Weiterhin aus v0.2

WICHTIG VOR INITIALCREATE
-------------------------
Wenn du bereits mit einem älteren Scaffold eine InitialCreate-Migration erzeugt
hast, lösche diese Migration für diesen Entwicklungsstand wieder, solange noch
keine produktiven Nutzerdaten existieren. v0.3 soll die erste verbindliche
InitialCreate-Basis sein.

Wenn noch keine InitialCreate existiert, ist nichts zu löschen.

INITIALCREATE ERZEUGEN
----------------------
Variante A - Eingabeaufforderung (empfohlen, wenn PowerShell-Skripte gesperrt sind):
  tools\create-initial-migration.cmd

Variante B - Befehle direkt im Terminal:
  dotnet tool restore
  dotnet ef migrations add InitialCreate --project src\BoardgameTracker.Infrastructure\BoardgameTracker.Infrastructure.csproj --context BoardgameTrackerDbContext --output-dir Persistence\SQLite\Migrations

Variante C - PowerShell:
  .\tools\create-initial-migration.ps1

Danach die Solution öffnen, kompilieren und die App starten.

WAS PASSIERT BEIM APP-START?
----------------------------
1. MAUI ruft App.CreateWindow auf.
2. Zunächst wird eine kleine Initialisierungsseite angezeigt.
3. DatabaseInitializer.InitializeAsync() erzeugt einen DbContext.
4. Database.MigrateAsync() prüft ausstehende Migrationen.
5. Bei einer frischen Installation wird die SQLite-Datei erzeugt und
   InitialCreate angewendet.
6. Anschließend wird AppShell als Root-Page des Fensters gesetzt.

Die Datenbankdatei liegt im MAUI-AppDataDirectory und heißt:
  boardgame-tracker.db

HINWEIS ZUR VALIDIERUNG
-----------------------
Dieser Scaffold wurde strukturell geprüft. In der Erstellungsumgebung steht kein
.NET-SDK zur Verfügung, deshalb konnte hier kein echter "dotnet build" ausgeführt
werden. Der entscheidende Build- und Migrationscheck erfolgt daher auf deinem
Entwicklungsrechner.
